# 任务级规格（Specs）

> **做什么**的契约，在任务开始前写、完成后验收。与 `.agent/tasks.md`（如何做的 playbook）互补。

## 生命周期

```
任务开始 ──写──▶ spec-*.md ──实现──▶ 按验收标准自检 ──▶ verify.mjs 门禁 ──▶ 关闭
                                                              │
                                                     通过: 归档或删除
                                                     失败: 回改 spec 或实现
```

- **创建**：任务拆解后、动代码前，新建 `spec-<slug>.md`（≤500 行/份）。
- **引用**：AGENTS.md 上下文预算约定「相关 spec 按需 1-2 份」，避免一次加载过多。
- **关闭**：验收标准全过 + `verify.mjs commit` 绿后，删除该 spec 或移入归档（避免堆叠过期货）。
- **防腐**：spec 是**临时契约**，不是长期文档——完成后必须清理，防止过期内容堆积。

## 文件清单

- `TEMPLATE.md` —— 规格模板（复制改名即用）。
- `archive/` —— 已完成的规格归档（可选）。

## 编写要点

1. **一份 spec 只含一个可验收的变更**，拆分粒度过细会产生大量过期文件。
2. **验收标准必须可机器/可观察验证**，禁止「感觉」「优化」这类模糊表述。
3. 边界写清楚「不做什么」，防范围蔓延。
4. 涉及前端洋葱/后端 DDD/存档字段时，先查对应分册再定边界。
